## 2. 架构选择

桌面容器暂选 Electron，新增 `apps/desktop`，复用 Web 的感知和调试代码。先建立独立桌宠窗口与感知 / 调试窗口的通信；验证后台帧处理不受普通页面隐藏或缩小影响。主进程只暴露必要窗口和配置接口，渲染端不直接获取任意文件系统能力。

后端统一处理规则、持久化调度、归因与 Bandit。两端仅提交可观察事件和交互行为，不各自训练独立模型。新增配置、干预链、观察结果、策略状态和奖励账本；沿用现有 Reminder 时建立兼容映射，避免未经迁移直接替换现有表结构。

以每用户原子决策 / 结算避免并发重复；时间统一服务端 UTC 保存、按用户时区计算上下文。视觉保持时长用单调真实时间，演示时钟独立标识。模型与奖励版本、决策概率、输入质量随决策保存。

## 3. 分阶段任务与交付

### P0：契约、配置和数据基础

任务：

- 创建 `packages/contracts`，定义用户配置、视觉特征、干预、展示回执、结果观察、情绪纠正及决策解释契约。
- 支持 30/60/90 分钟久坐、5/10/15/20 分钟休息，默认 60/10；忙碌状态、策略参数和用户时区持久化。
- 建立干预链和奖励结算表，纳入账号删除；建立现有 SQLite 数据的迁移方式，保留已有账号和记录。
- 用单独演示用户 / 命名空间隔离模拟数据与模型，增加输入来源标记。
- 更新失实或过期说明：45 分钟阈值、3 分钟冷却、共享契约目录及 Android 状态。

交付：配置 API、契约文档、可恢复的数据迁移和后端数据基础。

验收：非法配置拒绝；迁移保留原记录；用户隔离和删除正确；重启后配置不丢失。

### P1：修复观测，完成姿态和久坐闭环

任务：

- 修正五分钟姿态异常占比，使用按有效观察时间累计的滑动窗口；缺帧 / 遮挡不算正常姿态。
- 统一在岗防抖、久坐段、暂停 / 重启后的状态清理；避免异步 tick 重叠和同帧重复推理。
- 增加时序起身事件与坐椅平移排除，输出置信度和未知原因；提供录像 / 模拟测试输入。
- 接受提醒后创建实际动作状态；坐姿恢复 20 秒后进入 2 分钟复发观察。
- 起身休息按用户时长验证；区分结束久坐段、达到休息时长、动作证据不足。
- 所有结果关联干预 ID，处理已自然完成、延迟结果和相互重叠窗口，避免重复归因。

交付：可靠动作事件、状态快照和可查询的姿态 / 久坐闭环。

验收：正常恢复、复发、起身离开、坐椅平移、短暂遮挡及离线样例均有符合预期的结果。真实动作识别准确度待真人机位测试，模拟通过不能替代此项。

### P2：规则调度与在线学习

任务：

- 把规则改为确认参数：全类型主动文字交互至少间隔 15 分钟，滚动每小时最多 3 次，忙碌暂停，单干预互斥。
- 以实际展示回执更新预算；持久化延期任务、到期调度、失效 / 取消及服务重启恢复。
- 实现有限情境的折扣 Thompson Sampling，稀疏情境回退通用先验；策略包括不同干预及间隔、暂不打扰。
- 保存候选、过滤原因、选择概率与版本；未知结果不作负反馈，弱视觉线索降低权重。
- 奖励账本使用增量结算；接受不等于完成，延后不立即当拒绝，未来结果归入原干预链。
- 增加模型查询、解释、演示重置和回放接口；模型重置只作用于授权范围内的演示数据。

交付：可学习的频率和策略、真实重调度、解释与统计 API。

验收：固定随机种子的反馈序列能改变后续策略分布；未知序列不降低收益；并发 / 重试不突破预算或重复奖励；重启后延期仍生效。通过分布或回放验证学习，不能要求随机模型每次都立即选定某个动作。

### P3：表情观察和情绪陪伴

任务：

- 在本地感知层补充可见表情特征、质量评估及时间平滑；保留“无法判断”路径。
- 输出七类产品标签的假设与依据，建立抓拍自评 / 纠正入口；图片默认本地临时存在。
- 补交互前后观察窗口，输出可见表情变化和低权重可能打扰证据，不增加满意度调查。
- 情绪询问、温和陪伴、呼吸引导和暂不打扰使用受控模板；Router 可选生成表达，无凭证时模板可运行。
- 文本交互与姿态共用预算和学习服务；不存在可靠证据时不自动判定情绪改善或呼吸动作完成。

交付：可追溯表情观察、标签纠正、陪伴策略与闭环查询。

验收：自评纠正不篡改原始观察；低置信度可回退；不可见样本不产生负奖励；实际类别准确度单列验证，七个按钮存在不等于七类识别已可靠。

### P4：桌面容器及 Web 调试入口

任务：

- 建立 Electron 运行和 Windows 开发构建，复用 Web 感知模块；配置开发 / 打包资源路径，确保模型和 WASM 在容器中加载。
- 桌宠窗口实现透明 / 置顶 / 拖动 / 状态占位形象、文字交互、忙碌 / 暂停及退出。
- 感知、桌宠和调试窗口通信；验证隐藏、最小化及多窗口情况下仍只有一条感知与干预链。
- 用表单、按钮和 JSON 结果暴露全部后端能力，无需完整页面设计。
- 暴露真实摄像头、模拟 / 回放、时间加速及结果来源；提供学习状态和决策变化查看。

交付：可运行的 Windows 桌面容器、Web 调试入口和占位桌宠。

验收：桌宠可悬浮其他应用；摄像头权限与暂停明确；资源可加载；关闭桌宠不留下无法控制的感知进程；模拟不污染真实学习。

### P5：Android 调试客户端与跨端联调

任务：

- 用 ViewModel 接通登录、配置、忙碌状态、状态查询、提醒响应、观察记录、学习解释、日记和删除。
- 配置后端地址，区分模拟器 `10.0.2.2` 与真机局域网地址；不把固定模拟器地址当正式部署。
- 接入实时消息和断线补查；干预响应采用服务端幂等，两个端不能重复完成同一提醒。
- 提供模拟状态 / 事件 / 结果注入及明确标记，接收桌面感知结果演示同一闭环。
- 保留 `EufySdkGateway`；官方材料到手后实现 Adapter，不阻塞当前业务调试。

交付：连接真实后端的 Android Debug APK 和调试入口。

验收：静态提示替换为真实状态；两端配置和结果一致；重复响应可处理；断线重连恢复；APK 编译与模拟器运行通过。当前无设备，官方真机验收后置。

### P6：两端演示与交付检查

- 每端提供约 2 分钟的调试演示流程：输入 → 决策 → 展示 → 行为 / 观察结果 → 学习更新 → 后续策略变化。
- 以明确标注的加速回放展示 10 分钟休息、长期响应变化；另用真实时钟验证生产规则。
- 后端运行关键闭环测试，Web 构建，Electron Windows 开发 / 打包检查，Android assembleDebug 与模拟器联调。
- 交付启动说明、配置说明、API 调试清单、回放数据和未验证事项；不以模拟演示推导真实改善率。

## 4. 推荐执行顺序

先 P0 → P1 → P2，建立可独立验证的后端和姿态闭环；再 P3 补情绪观察；P4 和 P5 分别接桌面容器与 Android；最后 P6 验证两端演示。

桌面容器的摄像头 / 模型加载和后台运行风险，可在 P0 后先做最小技术验证，避免到后期才发现容器不适配。其余页面只做调试控件。

第一项实际开发任务应为：共享契约 + 用户可调配置 + 数据迁移；随即修复姿态滑动窗口并建立干预结果记录。没有可靠结果之前，不先训练在线策略。
