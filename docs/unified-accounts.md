# 统一用户名账号

Web、手机 App、电脑 SDK 感知端及桌宠共用 `POST /v1/auth/username`，输入 username/password。用户名可以是手机号、邮箱或自定义名称；采用 Unicode NFKC、去首尾空格、大小写折叠，不能为空。相同用户名始终映射同一 user_id，不同用户名隔离；新名字自动建号，无需注册。

密码任意、可空，不校验、不保存输入值。旧表的 password_hash 非空约束由随机不可用哈希满足，不是保存输入密码。底层业务外键仍是 user_id，username 只负责唯一映射。旧真实邮箱仍可作为用户名；旧邮箱密码接口保留兼容，但新版客户端不用它。

**这是用户指定的免校验演示登录，知道用户名即可进入账号，不适合真实隐私数据。仅 development/competition 显式设置 LOOKBUDDY_DEMO_LOGIN_ENABLED=true 时可用，production 禁用。**

## 使用

1. 重新部署后端/Web，保留 competition 与演示开关；重新构建安装 App。Git 推送不等于 Launch 自动部署。
2. 各端使用同一 HTTPS 后端和相同用户名，例如 `lookbuddy-demo`；密码随便填或留空。
3. 旧会话没有 username 时，客户端请求适配层不再加载旧会话，使用原有登录流程重新进入；不认领、不合并旧历史。不同用户名得到不同账号，旧数据库记录不清空。旧本机心情/工作时段不自动导入，未同步 Mark 不跨账号补传。
4. 页面恢复到本次账号改造前的原样，只改“手机号/邮箱”为“用户名”；Web 按用户确认额外取消邮箱格式和密码最短 8 位校验。原有“创建账号”“登录”按钮和页面切换不变，两者通过请求层映射到同一免注册登录接口。App 原短信/验证码按钮和流程保留外观，内容不会被服务端校验。没有新增提示、账号信息栏、迁移弹窗或联调入口。设置里原有安装隔离说明未扩改，实际归属以服务端统一 user_id 为准。
5. 电脑设备/SDK 上报使用统一登录响应的会话；桌宠复用电脑主窗口身份，不独立创建账号。eufy 供应商登录仅负责设备访问，不替代 LookBuddy 身份。

已撤掉假数据脚本、脚本授权导出入口及历史合并功能；保留常规单元测试和原有隔离后端客户端验证工具。没有删除云端数据库或代替用户部署。原 Launch 配置未显示持久化卷，重新部署前仍建议备份，避免误丢数据。
