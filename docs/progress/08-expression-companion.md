# P3 表情观察、标签纠正与陪伴闭环

日期：2026-10-08  
状态：代码、自动化测试与真实 HTTP 回放通过；真人识别质量、长期效果、桌面容器和 Android 联调尚未验收。

## 已交付

- Web 本地 MediaPipe 表情特征提取、时间平滑、可见性 / 正面角度 / 亮度检查，约每秒上传一次语义分数。原始画面、关键点和完整 blendshape 不上传。
- 七类状态标签及无法判断路径。标签属于可见表情假设；当前没有新增经过训练的情绪分类网络。置信分数为启发式分数，不是校准概率。
- 本地抓拍预览与自评确认 / 纠正。后台只保存抓拍关联信息及标签，不存图片；保存、取消、暂停或卸载后释放预览。自评为监督标签，不是满意度反馈，也不直接奖励陪伴策略。
- 情绪询问、温和陪伴、呼吸引导、暂不打扰四种策略。使用受控模板，无 Router 凭证亦可运行；尚未实现多轮陪伴对话。
- 干预前后视觉比较、版本化弱奖励、历史查询及独立 demo 学习。真实情绪候选仍遵守忙碌、用户开关、活跃干预和全局展示预算。

“专注”仅在手动忙碌上下文下给出假设，或通过用户自评确认；不能仅凭中性脸可靠识别专注。中性脸默认无法判断。可能压力较大 / 低落 / 愤怒均不是心理健康诊断。

## 观察与学习边界

触发前连续稳定假设至少 30 秒，并采集过去 30 秒基线，至少覆盖 24 秒。展示后观察即时 30 秒，随后继续观察 120 秒。即时覆盖至少 24 秒，随后覆盖至少 114 秒；间隔超过 3 秒、摄像头不可用或质量不足会进入未知结果，不当作拒绝。

比较微笑和眉部 / 嘴部紧张分数的时间加权平均，输出 `expression_relaxed`、`expression_tense` 或 `expression_unchanged`。记录实际展示回执，但不认为它证明用户看到或读懂；记录 `causalEffectProven=false`，不把时间上的变化视为干预造成的情绪改善。

学习采用 P2 的有限情境 Thompson Sampling，额外区分表情状态假设；数据少时仍使用同用户情绪类的合并后验。策略和间隔均有硬规则约束。视觉奖励独立使用 `expression-v1`：

- 可见表情放松给予 +0.10 弱奖励；已展示时计 -0.01 打扰成本，净值 +0.09。
- 同一方式在 7 天内至少出现 3 次表情变紧证据，才给予 -0.05 弱负奖励。首次或第二次只记录证据；静默观察不计消息打扰。
- 不变、未知或中断不产生视觉负奖励。自然接受 / 忽略 / 延后仍沿用已有交互证据，但不新增满意度调查。
- 不据表情判断呼吸动作完成，不发放姿态动作完成或持续改善奖励。纠正标签保留原始假设，暂不据此在线训练视觉网络。

还修正了饮水冷启动：没有饮水观察记录的工作会话先等待实际 90 分钟再生成候选，避免刚启动就把“未观察到”误当“未饮水”并占用提醒预算。

## 调试接口

所有接口均需登录，归属校验和幂等校验生效。

| 接口 | 用途 |
|---|---|
| POST `/v1/expressions` | 上传表达式语义特征，更新表情观察及陪伴结果 |
| GET `/v1/expressions?namespace=live或demo` | 查询原始状态假设、质量、时长及依据 |
| POST `/v1/emotions/captures` | 登记 captureId、expressionId、capturedAt，不接收图片 |
| POST `/v1/emotions/corrections` | correctionId、captureId、原假设和确认标签；原始观察不覆盖 |
| GET `/v1/emotions/corrections?namespace=live或demo` | 查询自评纠正历史 |
| GET `/v1/learning/preview?category=emotion&visualState=possibly_stressed` | 指定表情假设预览策略，仅调试，不创建提醒 |
| GET `/v1/learning/config` | 查看规则、窗口及表达式奖励版本 |

Web 调试页提供表情放松、变紧、不变、断流四种回放。回放使用明确的 demo 虚拟时间、独立观察和学习命名空间，不加速真实时间或污染 live 模型。重置 demo 同时清理关联模拟抓拍 / 自评；账号删除覆盖新表。
