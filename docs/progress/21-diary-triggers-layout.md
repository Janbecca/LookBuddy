# 日记分类、布局与三入口导航

Android版本：`1.4.2-diary-layout`，versionCode 12。

## 数据核查

本轮核查的是仓库中的事件生成、入库和日记投影代码，未连接用户线上地址，也未读取或修改设备同学保留的测试事件。

| 字段/来源 | 当前代码里的内容 | 解释 |
|---|---|---|
| `type` | `posture.bad_started` / `posture.bad_ended` | 坐姿相关事件 |
| `type` | `behavior.drink_detected` | 观察到饮水动作，和饮水提醒不同 |
| `type` | `behavior.yawn_detected` / `behavior.eyes_closed` | 疲劳相关可见线索，不作为健康诊断 |
| `type` | `behavior.break_completed` / `behavior.stretch_completed` | 休息或伸展完成 |
| `type` | `intervention.improved` / `recurred` / `unknown` 等 | 提醒闭环结果 |
| `payload.category` | `posture` / `sedentary` / `drink` / `fatigue` / `emotion` 等 | 提醒类别；闭环结果事件中由服务端明确保存 |
| `payload.reason` | 闭环判定原因代码 | 不是自然语言日记正文 |
| `source.rawType` / `payload.providerType` | 官方SDK的检测类型 | 不能把未核实的数值码映射成坐姿、久坐或饮水 |

官方日记媒体同步批次当前只有 `providerEventId`、`occurredAt`、`mediaItems` 等索引，不凭图片或SDK检测码猜健康触发原因。设备同学上传的单个事件是否实际含类别字段，仍需提供该事件的脱敏JSON或由其在现有后端核对。

新增 `diary_presentation.py`，日记接口返回 `eventType`、`triggerCategory`、`triggerLabel` 及已翻译的 `title/category/description`。对明确的已知事件、明确的产品类别做映射；未知类别保留“记录/设备事件”。保留原始note/description；不把饮水提醒当作已喝水，不把久坐提醒改善写成已完成运动。不改变数据库结构，不改写旧事件，不把图片带入分类结果。

## 界面变化

- 按用户最新要求移除底部第二个“陪伴视角”Tab，保留首页、陪伴日记、个人设置，等宽排列。摄像头仍可从首页右上角或个人设置的设备连接进入；摄像头详情页无独立底部选中项。更新项目导航约定，防止后续恢复旧四Tab规则。
- 登录后的页面使用完整窗口，移除额外的后端调试栏，解决真实运行比静态预览少一块高度的问题。后端设置移到“个人设置→系统设置”，未登录仍保留配置入口。全局错误使用临时Snackbar，不挤压页面。
- 正式入口启用固定产品主题和已打包的霞鹜文楷字体；正文、按钮、弹窗等默认文字统一，取消系统默认紫色按钮。首次注册显式指定的手写字体继续保留，不关闭系统字体缩放。
- 日记在小于约346dp宽度或字体缩放大于1.15倍时，切换为内容决定高度的气泡排布；使用“换一组日记气泡”代替固定高度的垂直分页，避免字体放大后文字截断。正常尺寸仍保留原来的气泡轮播。
- 真实日记卡片减少空白，时间不拆行，时间轴连接线随含图片的卡片高度延伸。底部点击区域小屏也至少48dp，首页抽屉同步计算导航高度。
