# P1 姿态与久坐动作闭环

日期：2026-10-08

## 已实现

姿态 / 久坐提醒关联干预 ID（与原 reminder ID 相同的一对一映射，无需修改旧表）。展示回执启动观察，接受提醒不等于动作完成。前端每秒上报低频语义视觉样本，后端验证并持久化状态和证据。

- 姿态正常连续 20 秒：记录动作完成，进入后续 120 秒观察。
- 后续异常持续达到现有规则的 60 秒阈值：记录复发。
- 后续结束时正常且窗口可持续观察：记录持续改善。
- 后续缺帧、画面不可靠或窗口末尾异常证据不足：记录未知，不判为改善或负反馈。
- 原始样本最大间隔为 3 秒；恢复前的缺帧重置连续计时，后续监测中的缺帧使结果未知。
- 起身识别要求可见腿部、既往屈膝坐姿、髋部上移、腿部伸直并保持 1 秒。此二维启发式未经真人准确度验证，0.8 是验证门槛标记而非校准过的概率。
- 确认起身后 15 秒内离开画面，开始离岗计时；健康视频帧持续存在且离岗时长达到用户配置，记录“起身及离岗时长达标”。不声称画面外一直站立 / 运动。
- 坐椅平移、只有人消失、没有可见腿部时，不确认起身。提前返回记中断；离岗过程中摄像头失效或缺帧记未知。
- 久坐只累计有效在岗观察，未验证离岗暂停但不清除历史；确认起身重置久坐段。
- 结果和观察关联干预、跨刷新持久化，完成后不再接受新样本；完全相同的样本重试不会重复记录，相同 ID 不同数据返回冲突。
- 单用户存在活跃姿态 / 久坐干预时不叠加新提醒；会话结束、观察期限结束记未知。

## API

| 方法与路径 | 用途 |
|---|---|
| GET `/v1/interventions?namespace=live或demo` | 查询干预与状态 |
| GET `/v1/interventions/{id}` | 查询详情，包括持久化的验证进度 |
| POST `/v1/interventions/{id}/displayed` | 幂等展示回执 |
| POST `/v1/interventions/{id}/samples` | 时序样本；校验时间、来源、状态、用户和去重 |
| GET `/v1/interventions/{id}/observations` | 最近观察及动作结果，可调整 limit |
| POST `/v1/debug/interventions` | 为指定活跃会话创建已展示的 demo 干预 |

模拟输入仅允许写 demo 干预；demo 使用独立时钟，可以发送未来样本以加速，结果不进入真实时间轴 / 日记。真实干预拒绝模拟来源和明显未来时间。

示例 demo 请求体：`{"sessionId":"当前会话ID","category":"posture"}`。

示例样本（时间必须含时区且不早于 displayedAt）：

```json
{
  "frameId": "唯一帧ID",
  "capturedAt": "2026-10-08T08:00:01+08:00",
  "source": "simulated",
  "cameraHealthy": true,
  "quality": "observable",
  "posture": "normal",
  "presence": "present",
  "standingConfidence": 0
}
```

真实客户端用 `source=webcam`。质量不足用 `quality=insufficient`、`posture=unknown`；视频帧存在而人离开用 `presence=away`。不直接提供“已改善”的任意结果，由后端从连续样本验证。

## Web 调试

新增六种按钮回放：正常恢复、恢复后复发、后续缺帧、坐椅平移、起身及规定离岗时长、提前返回。全部使用 demo 数据和加速时钟；配置的休息目标用于回放，运行不会改变真实模型。JSON 显示结果，API 控制台可继续查询观察证据。

摄像头链路中，提醒展示后自动上报视觉观察，页面显示动作状态与进度。每次开始重建感知 / 事件状态、要求重新校准，避免残留的上一会话计时。
