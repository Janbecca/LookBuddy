## 已完成里程碑

- M0：主办方资料、SDK 能力和安全边界基线。
- M1：eufy Web SDK 加载、四步鉴权、Provider 和 Live 画面链路。
- M2：`subscribeMediaChannelFrames` 裸帧接入本地 MediaPipe 感知。
- M3：Android App SDK 2.2.7 真设备代码链路和自动化验证。

最近一次自动化基线：后端 50 项通过；Web 25 项通过、1 项集成测试因未配置后端跳过；桌面 6 项通过；Android 12 项通过、1 项后端集成测试跳过，Lint 0 error。真机结论不包含在这些数字中。

Android 已设置为 `minSdk=24`。依据是主办方开发指南明确区分“SDK minSdk 24”和“示例 App minSdk 26”；直播材料另写 `minSdk <= 24`。选择 24 同时满足 SDK 标称下限和赛事直播口径，并通过完整 Gradle 构建验证依赖合并。API 24 真机运行仍属于现场验收，不由编译结果替代。

## 接下来按优先级执行

### M4：隐私与数据治理

- 首次启动知情同意和随时撤回。
- 明确禁止用于考勤、绩效、识别第三人和未成年人无授权场景。
- 将数据留存策略改为受控枚举，并由后端真实执行过期清理。
- 增加数据管理页：查看类别、清除观察历史、清除学习数据、删除日记和账号。
- 默认关闭表情陪伴和长期学习，用户主动开启后才生效。
- 绘制与代码一致的数据治理图。

### M5：赛事提交与演示

- 整理 6 分钟正式演示稿和断网/离线/超时降级话术。
- 固定 Windows 便携包与 Android APK，并记录校验值。
- 准备下一代硬件建议卡，每条建议对应真实演示证据。
- 至少进行两次完整计时排练。

### M6：真机和现场验收

- 使用真实赛事账号连接至少一款 T8171/T8214。
- 验证 Live、裸帧感知、设备状态、事件、缩略图和一次人工确认控制。
- 连续运行 15 分钟并验证断流、重连、停止释放资源。
- 在新 Windows 环境和 Android 真机完成安装。
- 按 [Android 真机验收表](android-eufy-device-acceptance.md) 留下设备、固件、网络、时间和结果证据。

## 完成定义

只有真实设备全链路通过、隐私治理与代码一致、自动化检查通过、6 分钟演示完成两次计时排练后，项目才能标记为“赛事准备完成”。
