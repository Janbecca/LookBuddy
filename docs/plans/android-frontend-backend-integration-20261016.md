将队友的 Android 产品页面 `apps/android-local` 接入现有 FastAPI 后端 `apps/backend`，交付可连接同一后端的完整 Debug APK。保留开屏、首次见面、日夜首页、心情日历、陪伴日记、陪伴视角和个人设置的视觉与交互。

后端基线包含当前本地尚未提交的 Launch 适配：competition 配置、SQLite WAL/权限检查、一致性备份、健康检查和 Dockerfile。这些改动需一并保留。部署由用户执行。

`apps/android` 保留为已验证的调试客户端和网络/SDK复用来源；产品页面使用 `apps/android-local`。不会将两个同包名 MainActivity 或两套 Gradle 工程直接混到一起。

## 3. 功能实施范围

### A. 手机号注册登录

- 沿用手机号/验证码页面，实现“验证码验证成功即登录，未注册手机号自动建账号”。
- 新增验证码发送、验证码登录及登录后绑定昵称的接口；手机号规范化为区号+号码，数据库设置唯一约束。
- 保留邮箱账号、旧登录接口和既有历史数据。调整用户共享模型支持 phone 与可空 email，旧端兼容手机号用户。
- 手机号不能仅凭输入就绑定或合并旧账号；关联旧账号须同时证明当前账号和手机号的所有权。
- 复用已有 access/refresh token、续期、退出与 Keystore 会话存储，替换“完成引导=已登录”的本地判断。
- 验证码有有效期、单次使用、重发间隔、手机号/IP限流、尝试次数限制；发码失败不显示成功。
- 抽象短信发送 Provider。开发/测试使用明确标记的隔离测试发送器；competition/production 没有真实 Provider 时拒绝发送和登录，不接受任意验证码，不回显验证码。

依赖：真实短信通道、签名和模板后续由用户配置。本次不采购短信服务，不索取明文凭据。

### B. 首页关心语

- 将队友独立 `backend/app.py` 的关心语能力整合进现有 FastAPI，不另起 5210 服务。
- 保留 `{scene, recent_message}` 请求和 `{show, message, source}` 响应形状，保留 `/buddy/greeting` 兼容入口，可同时提供 `/v1/buddy/greeting`。
- 按她的方法调用 GLM 标准接口，校验输出，超时/不可用时使用模板；`show=false` 正常隐藏气泡。
- 使用统一后端地址和真实登录身份，请求去重、短期缓存和访问限流，避免页面重组反复调用。
- 依据实际时间、工作计划及可用状态选择场景；没有真实在岗证据时使用未知状态，不把“计划上班”当作“人已落座”。
- 天气先保持明确标记的模拟/不可用来源，不将模拟天气当成真实天气。前端透出来源或避免将其写为事实。
- 本轮只做首页关心语，不增加主动健康提醒或动作学习闭环。

### C. 上下班、工作计划与真实会话

- 将最新页面已有的每日工作时段、时区配置保存到后端，支持跨夜，保留日夜素材与设备时钟展示。
- 复用创建和结束工作会话接口；补充当前会话查询、重复开始/结束的幂等行为及重启恢复。
- 将“计划工作时段”和“实际陪伴会话”分开：计划用于上下班展示、倒计时和场景；用户开始/结束陪伴才记录实际会话。自动到点不补造过去的工作时长。
- 在现有页面提供轻量开始/结束入口；手机后台、强退、跨日恢复时，依据会话状态与活跃证据处理，不将失联时段无限计入统计。
- 手机和桌面同时在线时，避免手机只看页面就创建第二段重复计时的会话；明确当前感知设备/会话的归属。

### D. 首页统计聚合

- 增加首页聚合接口，返回今日/本月有效工作时长、饮水次数、伸展次数、可确认休息时长、最新姿态状态、陪伴天数和各字段的数据质量。
- 按账号时区划分日期，跨午夜切分时长，重叠会话取并集，事件去重，区分 live 与 demo，默认聚合 live。
- 统计依赖结构化行为事实，不因点击接受或仅打开页面就增加饮水、伸展或休息次数。
- 当前不能可靠计算“专注时长”，页面改为“工作陪伴时长”；无法判断的状态显示“待观察”，空数据不伪造成良好状态。
- 提供最新感知状态查询和新鲜度字段，供手机展示电脑感知结果；不通过云端转发视频。
- 前端替换示例数字，并补齐加载、空状态、离线最近数据和错误状态。

### E. 每日心情自评，保留表情纠正

- 新增独立心情自评模型与接口：按日期保存/更新、读取某日、查询日期范围、删除。
- 保留开心/平静/有点累/低落四类，每用户每天一条，以账号时区计算日期，标记 `self_report` 来源。
- 现有表情观察、抓拍和纠正接口继续保留；自评不修改原始视觉观察，不自动作为满意度或学习奖励。
- 前端心情日历改为服务端数据；离线待同步需明确标记，不把保存失败显示为云端成功。
- 旧本机心情和昵称在用户登录后经确认一次性迁入，按日期幂等，不在两个账号之间自动共享。

### F. 陪伴日记适配

- 复用已有日记生成、读取、编辑和删除，增加按用户日期查询的时间线/页面聚合返回。
- 将 `occurredAt/type/payload` 等后端字段转成卡片所需时间、标题、描述和分类，保留明确的事实来源。
- 日期默认真实当天，保留最新队友代码中的日历体验；设计稿示例仅放独立演示入口，不混进真实历史。
- 日记只描述已发生的行为和主动记录，不生成未观察到的穿搭、收拾桌面或挥手下班等事实。
- 确保重新生成不会无提示覆盖用户已编辑的日记。
- 关键帧和 Mark 视频仅本地存在时，在原设备显示；其他设备显示“该媒体仅保存在原设备”，不展示可下载假链接。

### G. 摄像头 Adapter：前置能力验证

已找到官方材料：

- `【黑客松智能安防赛道】工具资料包/demo工程/AppSDKDemo/ESIotKit-DemoApp-Android/libs/ESIotKit-2.2.7.aar`
- `文档/app端/SDK开发指南-Android-iOS.md`
- `文档/app端/API参考手册-Android-iOS.md`
- `文档/app端/物模型高阶用法-Android-iOS.md`

现有 `EufySdkGateway` 可复用初始化、设备、事件、缩略图和隐私能力。新增 Adapter 接入产品页面的 `CameraFeed`，统一连接/断开、加载、离线、超时和资源释放。

官方 App SDK 指南明确指出不提供连续实时视频流/实时帧；高阶文档的 `EventMediaPlayer` 支持事件录像播放和下载。事件回放不能充当实时画面或点击前后精确10秒录制。

执行初期先核对 AAR 实际导出、官方示例及设备能力，分别验证：实时预览、可访问/编码的视频数据、本地录制和前滚缓冲。缺哪项就明确记录，不用截图占位冒充成功。

若 App SDK 确实缺实时能力，再验证复用已有 Web SDK 的 Android WebView/本地桥接方案；这属于技术验证，不预先承诺 WebView 兼容性或录像可行。

原生路径和替代路径都不可用时，暂停实时录像这一项并提交能力证据和可选方案供用户决定；设备事件和本地录像下载能力可独立交付，不能将其称为完整的实时摄像头验收。

### H. Mark：后端事件与本地视频

- 点击生成稳定 `markId/eventId`，后端保存时间、会话、设备和可选备注，复用 `memory.marked` 进入时间线与日记。
- 视频只保存录制设备本地，通过本地索引将 markId 关联至 MediaStore/持久可读 URI；URI不作为跨端资源地址。
- 录像链路具备能力时维护前5秒滚动缓冲，点击后再录5秒并保存；不足缓冲、断流、取消或写入失败时明确返回实际结果。
- 事件记录与媒体保存分别记录状态：标记成功不等于录像成功；同一点击重试不重复生成事件。
- 网络断开时本地保留待上传的标记元数据并幂等补传；录像仍留本地。后端不存连续视频、原始帧或手机 URI。
- 录像部分依赖 G 的能力验证；标记事件和日记接入不因此停工。

### I. 个人设置

- 增加本人资料读取/更新：昵称、时区；增加工作时段读取/更新，沿用已有久坐、休息等偏好接口。
- 手机号变更单独走验证流程，不能用普通资料 PATCH 改绑。
- 本轮头像保持现有本地占位，不新增头像上传或文件存储。
- 页面接通真实账号信息、退出、删除账号确认及系统工作时段设置；后端失败时保留可恢复的编辑状态。
- 账号删除覆盖新增手机号验证记录、心情、资料、Mark 元数据和关联业务数据；设备本地索引和缓存按用户隔离。

### J. 本轮不接提醒与动作闭环

- 保留现有后端规则、干预、学习和表情纠正能力，不删除或改坏旧客户端。
- 产品版 Android 暂不新增主动提醒展示、接受/稍后/忽略及动作结果验证入口。
- 产品版本轮优先查询状态、上传普通事实事件，不直接提交会触发提醒的快照。若确需新增快照上传，按该产品端会话明确禁用主动干预，避免默默生成无人处理的提醒或奖励；不关闭同账号桌面端已有功能。
- 关心语与每日自评不暗中接入学习奖励。

## 5. 接口草案

以下是待落实到共享 Schema/OpenAPI 的草案，不表示当前已经存在。

| 领域 | 建议接口 |
|---|---|

## 6. 验收与交付边界

- 数据迁移：旧邮箱用户/日记保留，新增手机号唯一，备份与恢复方式清晰。
- 身份：验证码过期/重放/错误/限流、发送失败、跨用户访问及登录续期正确；没有真实短信通道只标开发联调通过。
- 数据：工作时间不与计划时段混算、跨夜与重叠会话不重复、live/demo不混算、无数据不伪造统计。
- 心情与表情：每日自评幂等更新，抓拍纠正仍可用，两类来源不互相覆盖。
- 日记/Mark：重复上传不重复，离线补传正确，用户编辑不被覆盖，其他设备不显示本地视频下载成功。
- Android：产品工程编译、网络/数据测试、页面回归；尽量保持原 API24目标，若新UI依赖无法满足，先报告依赖证据，不盲目降版本。
- SDK：无凭据/无设备可验收接口与错误路径；真实鉴权、视频、录像和设备生命周期必须真机验证，不用模拟通过代替。
- 交付：独立整合分支与提交号、产品版 Debug APK、后端配置/迁移说明、可执行测试及未验证清单。
- 不执行 Launch 部署、短信采购或云端媒体存储建设。

## 7. 确认时需要明确的选择

1. 手机号方案按本计划采用“短信验证码，未注册自动注册”；真实 Provider 由用户配置，开发测试先隔离验证。
2. 工作计划只驱动展示，实际陪伴通过开始/结束控制，不自动补造工作时长。
3. 同意先验证 SDK 实时/录像能力；能力缺失时单独确认替代路径，不把事件录像回放当实时录像交付。

其余实现按上述范围推进；提醒与动作闭环保持后置。
