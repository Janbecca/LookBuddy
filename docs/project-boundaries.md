# 项目功能边界与双端分工

## LookBuddy 解决什么问题

LookBuddy 面向独立办公者，在用户主动开启后观察久坐、姿态、饮水、短暂离开和有限的可见表情变化，选择合适时机给出低打扰提醒，并记录用户是否接受、稍后或忽略。系统可以把经过筛选的事实整理成可编辑的工作日记。

它的重点不是“识别人是谁”，而是帮助当前用户看见自己的工作节奏，并让提醒根据反馈逐步减少打扰。

## 明确支持的功能

- 本地姿态与行为感知：久坐、姿态、饮水、打哈欠、闭眼等有限信号。
- 用户偏好：提醒阈值、休息目标、忙碌模式和提醒开关。
- 提醒闭环：展示预算、接受、稍后、忽略、动作验证和去重奖励。
- 工作日记：只使用已筛选事实，支持查看、编辑和删除。
- eufy Web：赛事鉴权、Live 展示、裸帧订阅和本地感知。
- eufy Android：设备列表、在线状态、事件、缩略图和人工确认的隐私模式控制。
- 离线开发：Webcam 和明确标记的模拟回放。

## 明确不做的事情

- 不做人脸身份识别、陌生人识别或员工追踪。
- 不判断心理疾病、人格、忠诚度、工作态度或工作绩效。
- 不把表情分类当作真实情绪、医学结论或行为证据。
- 不自动执行高风险设备控制；所有控制都由用户点击并二次确认。
- 不让大模型决定提醒、奖励、留存或日记事实。
- 不承诺休眠、锁屏或应用进入后台后仍能持续采集。
- 不把模拟数据包装成真实设备结果。

## 双端分工

| 能力 | Web / Windows 桌面端 | Android |
|---|---|---|
| 连续视觉感知 | 主端：eufy 裸帧或 Webcam + MediaPipe | 不负责姿态/表情识别 |
| Live 画面 | eufy Web SDK | 当前不作为主链路 |
| 设备在线状态 | 仅连接状态 | 主端：App SDK 设备列表 |
| 设备事件与缩略图 | Web SDK 本次赛事范围不承诺 | 主端：查询事件并按需取缩略图 |
| 设备控制 | 不实现 | capability 检查 + 二次确认后控制隐私模式 |
| 提醒与偏好 | 完整交互 | 调试和移动端交互 |
| 桌宠 | Electron 悬浮窗 | 不实现 |

两端共享同一个后端账号和服务端偏好。登录令牌分别保存在各自终端，不在 Web 和 Android 之间直接传递。

## 隐私边界

- 原始视频、连续帧、面部/姿态关键点默认留在终端。
- 后端只接收语义事件、低频状态和用户明确提交的反馈。
- eufy 和 Router 凭证只在运行时配置；真实值不得写入代码、文档或日志。
- 图片缩略图只按用户操作临时读取，不进入 LookBuddy 领域事件或后端长期存储。
- 用户必须能停止观察、断开设备并删除自己的业务数据。

## 当前可信程度

自动化测试可以证明接口、状态机和错误处理按预期工作，但不能证明真实设备、真实网络和真实摄像头识别效果。所有硬件能力在完成现场验收前都标记为“代码完成，待真机验证”。
