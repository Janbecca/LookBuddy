# LookBuddy 产品需求文档

版本：v1.0  
日期：2026-10-08（Asia/Shanghai）  
状态：已确认需求；标明“建议”的参数为实现初值，可配置、可调试  
主实现工程：`LookBuddy-main`；`LookBuddy-xyh` 为只读算法参考

## 1. 产品目标与本期范围

通过摄像头理解办公行为和可见表情线索，在合适的时机提供提醒或陪伴；持续观察干预后是否发生有效行动和改善，并根据实际行为调整下一次策略与提醒频率。

核心目标按优先级排列：持续改善 > 动作完成；打扰成本作为约束。接受提醒本身不等于干预成功。

演示覆盖 Web 技术栈的桌面端和 Android 端，每端约 2 分钟。本期不要求完整页面设计和布局优化，只要求将后端能力完整暴露为可测试、可调试的入口。桌宠采用桌面容器，能悬浮于其他应用之上；角色形象可以使用占位资源。

当前无官方设备、SDK 和真机测试条件。电脑摄像头、模拟事件及回放用于开发验证；必须明确标注模拟输入和时间加速。保留官方取流、事件与缩略图适配接口。

## 2. 端侧职责

| 端 | 本期职责 |
|---|---|
| Web / 桌面容器 | 本地视频感知、校准、动作验证、表情线索、抓拍自评、悬浮桌宠与文字交互、全部后端调试入口 |
| Android | 连接同一后端，查看状态、接收和响应干预、配置偏好、查看闭环与学习记录、模拟输入；预留官方 SDK |
| 后端 | 用户配置、事件存储、规则、策略学习、干预调度、结果归因、跨端同步和记录查询 |

第一版 Android 不承诺独立完成连续视频分析；可接收桌面感知端的结果。官方 SDK 公布后根据实际能力接入，不能把事件缩略图等同于连续视频。

同一用户共享配置和学习历史。同一时刻只允许一个有效干预，跨端展示不能重复计入干预次数或重复奖励。

## 3. 场景一：久坐 / 坐姿异常闭环

### 3.1 久坐配置

| 配置 | 选项 | 默认值 |
|---|---|---|
| 久坐触发时间 | 30、60、90 分钟 | 60 分钟 |
| 起身休息完成时间 | 5、10、15、20 分钟 | 10 分钟 |

阈值属于用户明确配置，在线学习不能擅自修改。达到阈值形成候选事件；是否此刻交互、选哪种策略及再次尝试的间隔由规则和学习策略决定。

起身认定要求观察到从坐姿起身并离开画面的过程。办公椅坐着平移离开不算起身。仅人脸消失、短暂遮挡或摄像头掉线不能算完成。

增加起身事件识别，结合躯干上移、髋部及腿部关键点、时序和离开轨迹。证据不足时记录“离岗，起身未验证”；完成结果保持未知，不发放动作完成奖励。画面外只能验证离岗持续时间，无法证明用户始终站立或运动，记录必须体现该边界。

建议：起身验证后开始休息计时，确认重新坐下则终止本轮休息；达成所选时长记“起身及离岗时长达标”。单次起身结束连续久坐段，但短暂起身不等于完成规定休息。具体防抖与置信阈值通过摄像头测试调整。

### 3.2 坐姿识别与结果

按主项目现有模型能力支持相对基线的前倾 / 相对距离过近、侧倾、高低肩。其他姿态不得仅因旧版说明提及就标记为已支持；扩展必须有模型实现和验证证据。

连续正常姿态 20 秒记动作完成，随后继续观察 2 分钟。观察期间异常再次达到有效判定阈值，记录复发；可观察且无复发，记持续改善；画面不足则记结果未知。20 秒和 2 分钟为真实观察时长，演示缩时必须明确标注。

### 3.3 干预方式

- 姿态轻提示。
- 短伸展。
- 短休息。
- 暂不打扰。

伸展可作为中间动作；不替代用户配置的起身休息完成标准。不同动作使用对应验证规则，不能全部以离开画面判定。

## 4. 场景二：表情线索 / 情绪陪伴闭环

支持产品标签：状态不错、专注、愉悦、可能压力较大、可能低落、可能愤怒、无法判断。

摄像头先输出可见表情特征和置信度，经过时间窗口形成情绪假设。单一微笑、皱眉或哈欠不足以稳定判断真实情绪；低置信度、遮挡、缺少可靠映射时输出“无法判断”。“专注”属于状态假设，不能由未检测到笑容直接推出。

支持抓拍后用户自评确认 / 纠正，用于完善情绪标签及误判记录。该入口不是每次干预后的满意度调查。用户不自评时，也不得伪造确认标签。

干预方式：情绪询问、温和陪伴、呼吸引导、暂不打扰。桌宠根据当前状态切换占位形象；状态线索累计达到一定时长才触发主动文字交互。累计窗口、触发阈值和文案模板做成配置，初值属于开发建议，需要测试调整。

不要求用户评价“有帮助 / 无帮助 / 更烦了”，干预结果通过视觉观察。保留接受、延后、忽略或关闭等自然交互行为。

建议结果观察：记录干预前 30 秒基线、展示后 30 秒即时反应、后续 2 分钟趋势，窗口均可配置。记录“微笑线索增加”“负向表情线索减少”等可见结果，不直接宣称实际情绪改善。表情中性或没有变化不等于失败；脸部不可见记未知。

本期呼吸引导的执行和情绪收益不能由现有摄像头可靠证明；可以记录可见反应，但不能凭提示结束自动判为呼吸动作完成。

## 5. 桌面桌宠

采用桌面容器，开发方案暂选 Electron，复用 React、MediaPipe 和视频源适配器。首个目标平台为当前开发环境 Windows。

最小能力：独立悬浮窗口、置顶开关、拖动、占位状态形象、文字交互、忙碌切换、暂停 / 退出、打开调试窗口。鼠标穿透作为可选功能，不能阻止用户操作桌宠。形象资产与状态枚举解耦，后续可替换。

摄像头感知与桌宠显示分离：关闭文字卡片不能停止观察；缩小或隐藏普通页面时仍需验证感知稳定性。明确显示摄像头运行状态，暂停感知后不产生新的视觉结果。

桌宠形象更新不计为主动提醒；首次显示或主动新增文字交互计入提醒预算。桌面容器不扩大画面上传范围。

## 6. 提醒频率和在线学习

### 6.1 已确认的规则边界

| 项目 | 初始设置 |
|---|---|
| 全类型主动文字交互最短间隔 | 15 分钟 |
| 全类型主动文字交互上限 | 每小时 3 次 |
| 可学习的间隔 | 15、30、60、120 分钟 |
| 并发干预 | 最多 1 个，结果观察期间不叠加 |
| 忙碌模式 | 用户手动切换；暂停主动文字交互，继续观察与记录 |
| 表情变化 | 低权重证据，多次一致才影响打扰判断 |
| 结果未知 | 不算忽略、失败或负反馈 |

建议按滚动 60 分钟执行次数上限，按服务端实际展示记录跨端去重。展示失败、仅创建候选事件不消耗已展示次数。增加展示投递保留和超时释放机制，避免并发下突破上限。

用户明确关闭某类能力、暂停感知等设置优先于学习策略。超时未响应与主动忽略分别记录，不能混为一谈。

### 6.2 方法选择

采用规则安全层 + 带时间衰减的 Contextual Bandit + 持续结果评估。规则负责用户配置、忙碌状态、间隔上限和干预互斥；Bandit 在允许的候选中选择干预方式及再次尝试间隔。

第一版建议采用分情境、有限策略组合的折扣 Thompson Sampling。按时间段、视觉状态、近期提醒负担和历史响应建立有限情境；样本少时回退到通用先验，不为每个用户创建过细情境。随着真实数据增加，可升级到共享参数的上下文模型。

选择理由：当前缺少大量真实样本，有限策略便于解释、调试和验证，且能在线更新。规则提供可靠冷启动；Bandit 适合单次干预的选择。复杂强化学习需要多步因果和大量数据，暂不采用。

“暂不打扰”必须作为可选策略。对其观察自然改善、待干预问题持续和零交互成本，不能因没有提示就固定奖励；无法观察仍记未知。记录选择概率，便于以后进行策略评估。

限制：数据稀疏、外部因素、观察延迟和用户习惯变化会影响学习；时间上的改善关联不等于因果证明。情绪表情收益尤其弱，不能与可靠动作验证赋予同等权重。

### 6.3 反馈和奖励

| 证据 | 用途 |
|---|---|
| 接受 | 小权重即时响应；不等同完成 |
| 延后 | 调整时机偏好；后续行动归因给原干预链，不立即当失败 |
| 忽略 / 关闭 | 明确交互负反馈，增加打扰成本 |
| 有效动作开始与完成 | 动作收益，区分视觉验证和调试注入 |
| 姿态持续恢复、起身及离岗时长达标 | 较高权重结果收益 |
| 干预后表情变化 | 低权重结果或可能打扰线索 |
| 未响应、无表情变化 | 未观察到效果；不认定厌烦，不自动增强强度 |
| 遮挡、离线、帧不足 | 结果未知，跳过该部分奖励更新 |

奖励结构：持续改善收益 + 动作完成收益 − 打扰成本。数值权重属于可配置实现参数，第一版须版本化记录；不采用此前讨论中未确认的具体加权数值作为产品定论。

延迟结果到达后只结算增量，重试不会重复奖励。长期无改善且交互成本升高时倾向更长间隔 / 暂不打扰；未知样本不降低策略收益。未确认用户看见提示时，负向表情只能记录交互后的关联线索，不能写成“用户被提醒惹烦”。

## 7. 记录和调试接口要求

每次干预记录：干预 ID、原干预链 ID、用户 / 会话 / 来源端、输入上下文、观察质量、候选策略、规则过滤原因、选择概率、模型与奖励版本、实际展示时间、自然交互响应、动作证据、前后窗口结果、奖励结算及下一次策略变化。

建议统一生命周期：候选 → 决策 → 待展示 → 已展示 → 响应 / 延后 → 动作开始 → 完成 → 后续观察 → 结算；分支包括抑制、关闭、过期、失败、结果未知。重调度不能靠用户再次上报恰好触发，服务重启后仍可恢复。

两端调试入口覆盖配置、状态和事件上报、干预响应、观察结果、情绪标签纠正、策略解释、模型统计、时间轴、日记与数据删除。模拟输入具有独立标识和隔离的学习状态；正式用户模型不得被演示回放污染。

## 8. 隐私和扩展性

原始视频和关键点默认本地处理，后端接收低频语义特征与事件。抓拍默认本地临时用于自评，用完释放；长期保存和上传不属于已确认需求。确认标签与不含画面的必要特征可持久化。新增学习数据纳入账号删除链路。

视频来源统一适配电脑摄像头、回放和未来官方 Web SDK；Android 通过 SDK Gateway 适配设备事件 / 缩略图。官方能力以发布材料及实测为准，不能猜测鉴权和数据接口。

## 9. 验收标准

1. 用户能配置久坐和休息选项，重启后仍有效；学习不改动明确阈值。
2. 起身离开与坐椅平移用正负样例验证；证据不足返回未知。
3. 姿态恢复 20 秒、后续 2 分钟无复发的闭环可追溯；断帧不误算持续改善。
4. 七类情绪标签和抓拍自评入口存在，低置信度可回退；记录区分标签假设、用户纠正和可见表情变化。
5. 不要求干预满意度反馈；视觉观察驱动结果，未知结果不算负反馈。
6. 多次有效反馈能够改变后续策略或间隔，并展示依据；刷新 / 重启仍保留学习状态。
7. 两端共用同一后端，重复响应和观察结果不产生重复学习；执行 15 分钟 / 每小时 3 次上限及忙碌约束。
8. 桌宠在桌面容器运行并可悬浮其他应用；两个客户端暴露完整调试能力。
9. 两端各可完成约 2 分钟的模拟 / 回放闭环演示；真实完整时长另行验证，演示不能证明长期真实效果。
